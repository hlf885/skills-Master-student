# 12 自绘图：先问需求，再看图库，由用户选画法（1.7.0 新增）

开题报告中需要自己画的图有四类：研究内容图（图2-1 类）、技术路线图、架构与框架图、算法流程图。文献原图不在此列，按 `05-research-plan-figures-formulas.md` 第五节处理。

这一流程来自本仓库作者的经历：图2-1 先后画过分层框图、五层四列，又出过横向闭环链、阶梯、环形三个候选，作者都不满意，参考国外博士论文后再出三个方向，最后才选定场景图加四步闭环。每一轮返工都是因为动笔前没有问清作者想要什么，也没有先让作者看到几种画法再选。

## 一、流程（每张自绘图都按此执行）

1. **问需求**：按第二节的问题清单提问。能用 AskUserQuestion 工具时用选择题，一次不超过 4 个问题；用户已经回答过的不重复问。
2. **展示图库**：把这类图的图库总览图和画法卡片发给用户（研究内容图见 `assets/figure-gallery/research-content/`）。总览图要让用户直接看到，不能只给文件名。
3. **给出推荐**：结合第 1 步的回答，按第四节推荐 1–2 种画法，写明推荐理由和不推荐其他画法的原因。推荐只是建议，最终由用户决定。
4. **画候选**：用户挑 2–3 种后，用用户自己的内容各画一张候选图（`draw_figure.py --style`），并排发给用户比较。
5. **选定与精修**：用户选定一种后再改细节，包括文字、配色、重点词、编号和箭头标注。
6. **选择交付格式**：说明三种格式的区别，由用户选择要哪几种。
   - **PNG**：直接插入 Word，约 300 dpi。
   - **SVG**：在 Visio 或 PowerPoint 中插入后可转为形状编辑。
   - **Visio 宏（.bas）**：在 Visio 中导入并运行后生成全部可编辑的形状，含场景图。
7. **同步正文**：改写正文中引用这张图的句子，使说法与新图一致（例如“四项研究内容在作业场景中对应的对象、前后衔接的产出以及实测偏差的反馈关系如图2-1所示”），并记入修改记录表。

Visio 宏的用法：打开 Visio，新建空白绘图，在“开发工具”选项卡点 Visual Basic，在编辑器中选择“文件 → 导入文件”，选中 .bas 文件，再在“立即窗口”输入 `DrawFigure` 后回车。有场景图时，宏会询问场景图所在的文件夹，场景图与 .bas 放在同一个文件夹即可。这一流程已在 Visio Professional 上实测通过。

## 二、问需求：问题清单

### 2.1 所有自绘图都要问

1. 这张图放在哪一节，正文里用它说明什么？
2. **主要给谁看？**分三档：
   - 懂行：本方向的专家；
   - 中间：相关领域的专家，懂工程或机器人，但不做这个方向；
   - 不懂行：其他学科的专家。
   答辩组通常混合，请用户说明以哪一档为主。
3. 必须出现哪些要素？哪些可以不画？
4. 有没有可以用的场景图、实物照片或模型截图？能否公开？涉密或项目内部的图只在用户本机使用，不放进公开仓库。
5. 版面限制：图宽（整页约 16cm，半页约 7.5cm）、最多占多少高度、字号不小于多少。
6. 学校模板或导师对这类图有没有要求？有没有用户认可的参考图，比如师兄师姐报告里的某张？
7. 配色和风格偏好：沿用全文统一配色，还是有其他要求？
8. 交付格式：PNG、SVG、Visio 宏中要哪几种？

### 2.2 研究内容图另外要问

- 研究内容有几项？各项之间是前后衔接、相互并列，还是围绕一个核心对象迭代？
- 是否要表达闭环反馈？反馈的内容是什么？
- 是否要在图中出现问题、关键问题、关键方法、预期结果、研究目标？哪些必须有？
- 有没有一个能代表课题的核心对象或核心概念，可以放在图的中心？

### 2.3 技术路线图另外要问（画法图库在后续版本补充）

- 按研究阶段组织，还是按研究内容组织？是否需要时间轴？
- 每个阶段要写方法、产出还是两者都写？成果栏不写论文（见 `02-section-guide.md`）。
- 是否要和图2-1 使用同一套结构和配色？

### 2.4 架构与框架图另外要问（画法图库在后续版本补充）

- 要表达的是分层结构、模块与数据流，还是虚拟与实体之间的映射？
- 各层或各模块的名称是否已经确定？层与层之间传递什么数据？

### 2.5 算法流程图另外要问（画法图库在后续版本补充）

- 有没有离线与在线两个阶段需要分开？
- 有没有判断分支或循环？失败时怎么处理？
- 每一步是否要标出对应的公式编号？

## 四、研究内容图的推荐规则

| 用户的情况 | 首选 | 备选 |
| --- | --- | --- |
| 有清晰的场景图，读者混合，内容有前后衔接和反馈 | R8 | R7 |
| 有场景图，内容相对并列，读者以不懂行为主 | R7 | R8 |
| 没有场景图，读者以不懂行或中间档为主 | R6 | R3 |
| 读者以懂行为主，学校或导师习惯模板式框图 | R1 | R2 |
| 要求问题、方法、结果一一对应 | R2 | R1 |
| 强调逐级递进，不需要反馈 | R4 | R3 |
| 内容围绕一个核心对象反复迭代 | R5 | R6 |
| 理论性强，以研究问题组织全文 | R9 | R1 |

推荐时说清两点：为什么推荐它，它在这个课题上的不足是什么。不要只推荐作者本人用过的 R8。

## 五、画图的通用要求

- 图中不写题目，不写写作说明（如“（输入研究内容3）”），不用分号；
- 每个框只写名称和一句话，全图字数尽量控制在 80–150 字，插入 Word 后图中字号约 8–9 pt；
- 同一含义用同一颜色：问题用橙色，内容和目标用蓝色，产出用绿色，反馈用醒目的橙色线；
- 场景图中用编号标出各项研究内容作用的部位，编号与右侧或下方的条目一致；
- 场景图与正文中的其他图重复时，提醒用户可以换一个角度截图；
- 画完先用 PNG 发给用户看，用户确认后再生成其他格式。

# 02 各部分写法、字数与句式

本文件由 9 份同领域（机器人、数字孪生、SLAM、强化学习、力/视觉控制、辐照可靠性等方向）硕士开题报告归纳而来，提炼的是结构、篇幅、写作边界和表达习惯，不含任何原文段落。量化统计见 `09-template-benchmarks.md`。

## 总体结构（学校常用表格式开题报告）

```
封面：硕士研究生学位论文开题报告（学号、姓名、学院、专业、研究方向、导师、学位、日期）
表头：论文题目｜选题来源｜论文类型（应用研究）｜开题日期｜开题地点
一、立题依据（不少于 800 字）
    1. 选题依据
    1.1 研究目的及意义
    1.2 国内外研究现状（1.2.1 … 1.2.n）
    1.3 发展趋势
    1.4 参考文献
二、研究内容和目标（不少于 2500 字，重点）
    2.1 研究内容　2.2 研究目标　2.3 拟解决的关键问题
三、研究方案设计及可行性分析（不少于 800 字）
    3.1 拟采取的研究方案（研究方法、技术路线）　3.2 理论分析　3.3 可行性分析
四、本研究课题可能的创新之处（不少于 500 字）
五、研究基础与工作条件（不少于 500 字，用户本人撰写）
学位论文工作计划（表格：时间｜研究内容｜预期效果）
```

编号习惯：节号“1.1”“1.2.1”；图“图1-1”、表“表3-1”、公式“(3-1)”，全文统一一种（推荐短横线）。正文称“本课题”或“本研究”，全篇统一，不与“本文”混用。

## 一、立题依据

### 1.1 研究目的及意义——写成“项目立项必要性”

开题报告是应用研究，1.1 的任务是让评审相信：**这件事必须做、现在做正合适、你依托的项目正是为它立项的。**

推荐五步：

1. **国家与行业需求**（2–4 句）：从国家战略、行业规划或产业现状切入（如智能制造、特种机器人、核能安全、人工智能发展规划），引用权威文件或数据，不空喊口号。
2. **应用场景与现有做法**（1 段 + 1 组图）：典型场景是什么，现在靠什么做（人工、半自动设备、传统算法），配场景图（2×2 子图常见，子图标注 (a)(b)(c)(d)）。
3. **痛点与根源**（1–2 段）：现有做法的问题——安全风险、效率、精度、适应性、可靠性；再进一步说清**为什么**现有技术解决不了（结构性原因），可用“（1）……（2）……（3）……”列出该类系统的特点或挑战。
4. **使能技术与机会**（1 段）：引出本课题采用的关键技术（如数字孪生、多源融合、模仿学习），说明它为何能对症下药，避免泛泛夸技术。
5. **本课题做什么、意义何在**（1 段）：“为解决上述问题，本课题依托××项目，开展……研究，旨在……”；意义分科学意义与工程应用价值，最好与项目考核要求呼应。

要求：引用密度高（1.1 通常引用 [1]–[15]）；不出现具体技术方案细节；不写成项目申报书的大话。

### 1.2 国内外研究现状——层层递进，显示思考

**组织原则**：小节按“研究内容的技术层次”排序，而不是按国家或年份堆砌。常见做法是每个研究内容对应一个 1.2.x 小节，必要时在前面加一个“研究对象/领域总体现状”小节。

**每个小节的内部结构（四层递进）**：

1. **引入**（1 段）：这项技术在整个系统中起什么作用，研究重点如何随应用场景变化而转移。
2. **演进脉络**（2–5 段）：经典/奠基工作 → 针对其缺陷的改进 → 学习型/数据驱动方法 → 近 3 年最新进展；国外、国内都要有。每段围绕一类方法，而不是一篇文献一段。
3. **代表性工作**：句式“××等[n]针对……问题，提出了……方法，通过……，在……上验证了……”；关键工作给出量化结果（若原文有）；适当插入 1–2 幅代表性工作图。
4. **评述与缺口**（1 段）：“综上所述／总体来看，……已取得……进展，但仍存在以下不足：一是……；二是……；三是……。”这些不足要能直接对应到本课题的关键问题。

**体现思考的技巧**：
- 比较方法之间的取舍（实时性 vs 精度、模型驱动 vs 数据驱动），而不是只说“效果很好”；
- 指出前人工作的适用条件和局限（场景、假设、数据规模）；
- 小节之间用一句话承上启下，让读者看到“感知→规划→控制”或“系统→部件→芯片”这样的层次。

**表格可选**：方法对比表（方法｜优点｜局限｜适用场景）能让评述更清楚，每节最多 1 张。

### 1.3 发展趋势

- 从 1.2 归纳的不足推出 3–4 条趋势，每条“（1）标题句 + 一段说明”；
- 趋势要具体到技术方向（如“风险量化从静态阈值走向动态自适应”），避免“智能化、网络化、集成化”式空话；
- 最后一段把趋势落到本课题：“本课题所研究的……正是上述趋势中的……方向。”

### 1.4 参考文献

见 `04-citation-gbt7714.md`。56–66 条；按正文首次引用顺序编号。

## 二、研究内容和目标（重点部分）

### 2.1 研究内容

**结构**：

1. **导语段**（150–300 字）：一句话概括对象和总体问题，再归纳 2–3 个核心挑战（与 1.2 的不足呼应），最后“本课题主要研究内容如图2-1所示”。
2. **研究内容框图**（图2-1，Visio 绘制）：采用分层框图，一眼看清逻辑。自上而下为：题目框 → **发现问题**（2–3 个痛点，来自 1.1）→ **研究目标**（一条总目标横框 + 与研究内容一一对应的分目标）→ **研究内容**（3–4 项）→ **关键问题**（与 2.3 对应）。每层用圆角虚线框包住，左侧写层名（“发现问题”“研究目标”“研究内容”“关键问题”，两字一行），问题层与关键问题层用黄色虚线、目标层与内容层用蓝色虚线；每层之间用竖向箭头逐列对应；每个框中的**重点词标红**（如总目标中的“自动生成、筛选、验证”）。配色见 `05-research-plan-figures-formulas.md`，规格示例见 `assets/figure-spec-research-content.json`。
3. **研究内容条目**（3–4 项，最后一项通常是“系统集成与实验验证”）：

**每一项的写法（用户硬性要求）**：
- 标题：“（1）面向××的××方法研究”或“××系统设计”，与题目关键词对应；
- 正文**浓缩为一句核心话**，展开后约 **4–5 行（120–220 字）**；
- **只说做什么**：针对什么问题、研究什么对象、要得到什么结果；**不说怎么做**（不出现具体算法步骤、公式、软件操作）；
- **环环相扣**：前一项的输出是后一项的输入（如“为后续……提供……”）；
- **与题目相切**：题目中的每个关键词至少在一项内容中出现。

**示例（结构示意，内容请按用户课题重写）**：

> （1）狭长管廊环境下巡检机器人定位退化机理与建模研究
> 针对管廊结构重复、特征稀疏导致机器人定位误差持续累积的问题，研究定位误差随环境特征变化的规律，建立能够表征定位可信程度的退化模型，为后续巡检路径规划提供可用的定位置信信息。
>
> （×）反例：“采用 LiDAR 与 IMU 紧耦合因子图，利用 ICP 配准并引入鲁棒核函数……”——这是研究方案，应放到第三部分。

篇幅不足 2500 字时，**不要**把方案塞进研究内容；应充实 2.1 导语、2.2 目标的指标与验证方式、2.3 关键问题的难点分析。

### 2.2 研究目标

- 一段总目标（这项研究最终交付什么能力/系统）+ 与研究内容一一对应的分目标（1）（2）（3）；
- 分目标句式：“研究/构建/实现一种……，使……达到……”；
- **量化口径按阶段 2 用户的选择**：
  - 用户选“量化”：写出指标、数值、测试条件，如“在××场景下任务成功率不低于 80%”“虚实同步时延小于××ms”；数值必须来自项目文件或用户确认；
  - 用户选“定性”：写清可检验的效果和验证方式（与什么基线对比、看哪些指标的变化趋势），避免“显著提升”而无验证手段。

### 2.3 拟解决的关键问题

- 2–3 个，每个“（1）××问题”+ 1–2 段；
- 每段讲清：**为什么难**（机理层面：耦合、不确定性、高维、实时性、小样本……）→ **不解决会怎样** → **需要突破什么**（“需……，重点解决……”）；
- 关键问题是“难点”，不是研究内容的复述；与创新点对应但措辞不同。

## 三、研究方案设计及可行性分析

写之前必须先完成《可行性—难度—工作量评估表》（见 `05-research-plan-figures-formulas.md`），用户认可后再写。

### 3.1 拟采取的研究方案

- 研究方法一句话：“本课题将采取理论分析、仿真验证与实物实验相结合的研究方法”；
- **技术路线图**（图3-1，Visio）：左侧阶段（调研→建模→算法设计→仿真验证→实物验证），中间研究内容，右侧输出；
- 路线说明：“第一步……第二步……”或（1）（2）（3），每步写清输入、做法、输出，与研究内容一一对应。

### 3.2 理论分析（按研究内容分节）

每个 3.2.x 对应一项研究内容，内部结构：

1. 本节要解决什么（一句话，回扣关键问题）；
2. 系统/模型描述（结构图 + 数学模型）；
3. 拟采用方法的原理（必要公式，编号（3-n），公式后用“式中，……”解释每个符号）；
4. 拟改进之处（基于原理指出改进思路，用“拟”）；
5. 本节输出及与下一节的衔接。

公式要“必要”：用于定义问题、给出模型、说明改进点；不堆砌教科书推导。每个公式后都有符号说明；变量用斜体，矩阵向量用粗体。

### 3.3 可行性分析

可行性分析是**学生本人**向专家说明“我有能力、有条件开展这项学术研究”，不是项目经理汇报进度和风险。按模板写成三方面加一句总结：

1. **在理论基础方面**：本课题依托哪些成熟理论（如运动学、可达性分析、采样规划），本课题要在此基础上**探索哪些尚未解决的问题**（写成学术问题，而不是工程任务）；本人通过文献调研和课程学习掌握了哪些理论（如实写，不编造课程名）。
2. **在技术储备方面**：本人已掌握或正在学习的软件、算法和工具（如 Unity 场景搭建、ROS 通信、开源规划库），它们能完成哪些基础计算，使研究精力集中在方法问题上。
3. **在研究条件方面**：依托的项目、实验室平台、设计资料、模型与计算设备、现场条件。
4. 结尾一句：“综上所述，基于现有的理论基础、技术储备和研究条件，本课题的研究方案切实可行。”

禁止事项：
- **不引用文献**，不出现上标引用；
- 不写难度分级、人·月、降级方案、退路、“若做不出来则……”，这些放在内部的《可行性—难度—工作量评估表》中供用户和导师讨论，不进正文；
- 不写“由项目方提供数据”“待项目方确认”等项目协调口吻；
- 涉及用户本人学习、实践、设备条件的句子，用户未提供依据时**加黄色底纹**（Markdown 写作 `[句子]{.mark}`），交付时提醒用户核对后去掉底纹；
- 可用第一人称“我”（与参考模板一致），其余各部分仍统一用“本课题”。

## 四、本研究课题可能的创新之处

- 2–3 条，标题“4.1 拟提出一种……方法”/“拟改进一种……”；
- 每条 250–400 字：针对什么不足 → 核心思路（与已有方法的关键区别） → 预期带来什么；
- 慎用“首次”“国际领先”“彻底解决”；能说清“继承了什么、增加了什么、在哪个机制上不同”即可。

## 五、研究基础与工作条件（用户本人撰写）

不代写。输出以下提纲并提醒：

> 第五部分需要你本人撰写（不少于 500 字）。建议提纲：

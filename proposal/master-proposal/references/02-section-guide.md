# 02 各部分写法、字数与句式

本文件由 9 份同领域（机器人、数字孪生、SLAM、强化学习、力/视觉控制、辐照可靠性等方向）硕士开题报告归纳而来，提炼的是结构、篇幅、写作边界和表达习惯，不含任何原文段落。量化统计见 `09-template-benchmarks.md`。

## 总体结构（学校常用表格式开题报告）

```
封面：硕士研究生学位论文开题报告（学号、姓名、学院、专业、研究方向、导师、学位、日期）
表头：论文题目｜选题来源｜论文类型（应用研究）｜开题日期｜开题地点
一、立题依据（不少于 800 字）
    1. 选题依据
    1.1 研究目的及意义
    1.2 国内外研究现状（1.2.1 … 1.2.n）
    1.3 发展趋势
    1.4 参考文献
二、研究内容和目标（不少于 2500 字，重点）
    2.1 研究内容　2.2 研究目标　2.3 拟解决的关键问题
三、研究方案设计及可行性分析（不少于 800 字）
    3.1 拟采取的研究方案（研究方法、技术路线）　3.2 理论分析　3.3 可行性分析
四、本研究课题可能的创新之处（不少于 500 字）
五、研究基础与工作条件（不少于 500 字，用户本人撰写）
学位论文工作计划（表格：时间｜研究内容｜预期效果）
```

编号习惯：节号“1.1”“1.2.1”；图“图1-1”、表“表3-1”、公式“(3-1)”，全文统一一种（推荐短横线）。正文称“本课题”或“本研究”，全篇统一，不与“本文”混用。

## 一、立题依据

### 1.1 研究目的及意义——写成“项目立项必要性”

开题报告是应用研究，1.1 的任务是让评审相信：**这件事必须做、现在做正合适、你依托的项目正是为它立项的。**

**1.6.0 起按八段漏斗写**（各段任务、首句写法、示例和填空骨架见 `11-argument-chain.md` 第三、七节）：① 国家与行业 → ② 需求的普遍性 → ③ 依托项目与研究对象 → ④ 研究边界 → ⑤ 核心概念与困难 → ⑥ 现有方法为何不能直接用 → ⑦ 方法手段为何合适 → ⑧ 因此与意义。下面的五步是旧版写法，可作补充参考：

1. **国家与行业需求**（2–4 句）：从国家战略、行业规划或产业现状切入（如智能制造、特种机器人、核能安全、人工智能发展规划），引用权威文件或数据，不空喊口号。
2. **应用场景与现有做法**（1 段 + 1 组图）：典型场景是什么，现在靠什么做（人工、半自动设备、传统算法），配场景图（2×2 子图常见，子图标注 (a)(b)(c)(d)）。
3. **痛点与根源**（1–2 段）：现有做法的问题——安全风险、效率、精度、适应性、可靠性；再进一步说清**为什么**现有技术解决不了（结构性原因）。困难、特点用自然段叙述，不编号（1.6.0：用户在稿中删去了困难段的编号）。
4. **使能技术与机会**（1 段）：引出本课题采用的关键技术（如数字孪生、多源融合、模仿学习），说明它为何能对症下药，避免泛泛夸技术。
5. **本课题做什么、意义何在**（1 段）：“因此，以××为研究对象，开展……研究，具有……意义”；意义分理论意义与工程价值。

**依托项目只说一次**：在 1.1 介绍应用场景时用一句话写明“本课题依托××项目”，之后全文不再反复出现“项目”“项目方”“项目要求”“项目设计资料”，改用研究对象（偏滤器拆卸、主臂）、“设计资料”“装置”“现有模型”等说法。“本课题”全文控制在 4–12 次，多数句子直接以研究对象或方法作主语。

要求：引用密度高（1.1 通常引用 [1]–[15]）；不出现具体技术方案细节；不写成项目申报书的大话。

### 1.2 国内外研究现状——层层递进，显示思考

**组织原则**：小节按“研究内容的技术层次”排序，而不是按国家或年份堆砌。1.6.0：小节按应用领域、方法载体、核心技术、支撑技术四种角色由外到内排列，小节内部按“分类标准 → 递进排列的类别 → 本对象定位句 → 小结”展开，见 `11-argument-chain.md` 第四节。常见做法是每个研究内容对应一个 1.2.x 小节，必要时在前面加一个“研究对象/领域总体现状”小节。

**每个小节的内部结构（四层递进）**：

1. **引入**（1 段）：这项技术在整个系统中起什么作用，研究重点如何随应用场景变化而转移。
2. **演进脉络**（2–5 段）：经典/奠基工作 → 针对其缺陷的改进 → 学习型/数据驱动方法 → 近 3 年最新进展；国外、国内都要有。每段围绕一类方法，而不是一篇文献一段。
3. **代表性工作**：句式“××等[n]针对……问题，提出了……方法，通过……，在……上验证了……”；关键工作给出量化结果（若原文有）；适当插入 1–2 幅代表性工作图。
4. **评述与缺口**（1 段）：“综上所述／总体来看，……已取得……进展，但仍存在以下不足：一是……；二是……；三是……。”这些不足要能直接对应到本课题的关键问题。

**体现思考的技巧**：
- 比较方法之间的取舍（实时性 vs 精度、模型驱动 vs 数据驱动），而不是只说“效果很好”；
- 指出前人工作的适用条件和局限（场景、假设、数据规模）；
- 小节之间用一句话承上启下，让读者看到“感知→规划→控制”或“系统→部件→芯片”这样的层次。

**表格可选**：方法对比表（方法｜优点｜局限｜适用场景）能让评述更清楚，每节最多 1 张。

### 1.3 发展趋势

- 从 1.2 归纳的不足推出 3–4 条趋势，每条“（1）标题句 + 一段说明”；标题写成“××从 A 走向 B”，全部趋势后用一句收束语把方法关键词和对象放在同一句里扣回题目（见 `11-argument-chain.md` 第五节）；
- 趋势要具体到技术方向（如“风险量化从静态阈值走向动态自适应”），避免“智能化、网络化、集成化”式空话；
- 最后一段把趋势落到本课题：“本课题所研究的……正是上述趋势中的……方向。”

### 1.4 参考文献

见 `04-citation-gbt7714.md`。56–66 条；按正文首次引用顺序编号。

## 二、研究内容和目标（重点部分）

### 2.1 研究内容

**结构**：

1. **导语段**（150–300 字）：一句话概括对象和总体问题，再归纳 2–3 个核心挑战（与 1.2 的不足呼应），用名称说明各项内容之间的关系，最后一句“具体研究内容如下，如图2-1所示：”，紧接框图和条目。
2. **研究内容框图**（图2-1，Visio 绘制）：采用分层框图，一眼看清逻辑。自上而下为：题目框 → **发现问题**（2–3 个痛点，来自 1.1）→ **研究目标**（一条总目标横框 + 与研究内容一一对应的分目标）→ **研究内容**（3–4 项）→ **关键问题**（与 2.3 对应）。每层用圆角虚线框包住，左侧写层名（“发现问题”“研究目标”“研究内容”“关键问题”，两字一行），问题层与关键问题层用黄色虚线、目标层与内容层用蓝色虚线；每层之间用竖向箭头逐列对应；每个框中的**重点词标红**（如总目标中的“自动生成、筛选、验证”）。配色见 `05-research-plan-figures-formulas.md`，规格示例见 `assets/figure-spec-research-content.json`。
   图2-1 之后直接写条目（1），**不要**再加“下面分别说明四项研究内容各自针对的问题和要得到的结果”这类讲稿式过渡句；也不要在条目之前按编号描述各项关系（读者还没看到（1）（2）（3）），关系放在导语中用名称说明。
3. **研究内容条目**（3–4 项，最后一项通常是“系统集成与实验验证”）：

**每一项的写法（用户硬性要求）**：
- 标题：“（1）面向××的××方法研究”或“××系统设计”，与题目关键词对应；
- 正文**浓缩为一句核心话**，展开后约 **4–5 行（120–220 字）**；
- **只说做什么**：针对什么问题、研究什么对象、要得到什么结果；**不说怎么做**（不出现具体算法步骤、公式、软件操作）；
- **环环相扣**：前一项的输出是后一项的输入（如“为后续……提供……”）；
- **与题目相切**：题目中的每个关键词至少在一项内容中出现。

**示例（结构示意，内容请按用户课题重写）**：

> （1）狭长管廊环境下巡检机器人定位退化机理与建模研究
> 针对管廊结构重复、特征稀疏导致机器人定位误差持续累积的问题，研究定位误差随环境特征变化的规律，建立能够表征定位可信程度的退化模型，为后续巡检路径规划提供可用的定位置信信息。
>
> （×）反例：“采用 LiDAR 与 IMU 紧耦合因子图，利用 ICP 配准并引入鲁棒核函数……”——这是研究方案，应放到第三部分。

篇幅不足 2500 字时，**不要**把方案塞进研究内容；应充实 2.1 导语、2.2 目标的指标与验证方式、2.3 关键问题的难点分析。

### 2.2 研究目标

- 一段总目标（这项研究最终交付什么能力/系统）+ 与研究内容一一对应的分目标（1）（2）（3）；
- 分目标句式：“研究/构建/实现一种……，使……达到……”；
- **量化口径按阶段 2 用户的选择**：
  - 用户选“量化”：写出指标、数值、测试条件，如“在××场景下任务成功率不低于 80%”“虚实同步时延小于××ms”；数值必须来自项目文件或用户确认；
  - 用户选“定性”：写清可检验的效果和验证方式（与什么基线对比、看哪些指标的变化趋势），避免“显著提升”而无验证手段。

### 2.3 拟解决的关键问题

- 2–3 个，每个“（1）××问题”+ 1–2 段；
- 每段讲清：**为什么难**（机理层面：耦合、不确定性、高维、实时性、小样本……）→ **不解决会怎样** → **需要突破什么**（“需……，重点解决……”）；
- 关键问题是“难点”，不是研究内容的复述；与创新点对应但措辞不同。

## 三、研究方案设计及可行性分析

写之前必须先完成《可行性—难度—工作量评估表》（见 `05-research-plan-figures-formulas.md`），用户认可后再写。

### 3.1 拟采取的研究方案

- 研究方法一句话：“根据研究目标和研究内容，拟采用理论分析、仿真验证与实物实验相结合的研究方法”，再用一两句说清总体思路，然后“技术路线如图3-1所示”；
- **技术路线图**（图3-1，Visio）：左侧研究阶段，中间研究内容与方法，右侧阶段成果；成果栏写模型、方法、数据和实验结论（如“对比与消融结果”“虚实偏差分析”），**不写“学术论文”“学位论文”“专利”**，这些放在工作计划的预期效果里；
- 路线说明照样本写成“本方案的研究具体路线如下：（1）……；（2）……；（3）……”，每条一两句，讲做什么、怎样衔接；**不用**“第一步……输出为……”这种项目计划书的写法。

### 3.2 理论分析（按研究内容分节）

每个 3.2.x 对应一项研究内容，内部结构：

1. 开头直接进入内容（研究对象是什么、为什么需要这样建模或求解），**不写**“本节对应关键问题（1）”“本节的目标是……”这类对照说明，对应关系已在 2.1 框图中体现；
2. 系统/模型描述（结构图 + 数学模型）；
3. 拟采用方法的原理（必要公式，编号（3-n），公式后用“式中，……”解释每个符号）；
4. 拟改进之处（基于原理指出改进思路，用“拟”）；
5. 自然过渡到下一节（如“法兰候选还需由主臂在腔内实现”），不写“本节输出为……”。

**实验验证的写法**：按计划直接写实验内容和步骤，如样本中的“采用数字孪生系统与实体机器人联合调试的方法……首先进行虚实双向控制实验……然后……接着……”。不要写“条件具备时开展”“经项目方许可后进行”“偏差数据不足时先按……设定”这类自我设限的条件句，专家会直接追问“条件不具备怎么办”。现场安全、审批等属于执行细节，不进正文。

公式要“必要”：用于定义问题、给出模型、说明改进点；不堆砌教科书推导。每个公式后都有符号说明；变量用斜体，矩阵向量用粗体。

### 3.3 可行性分析

可行性分析是**学生本人**向专家说明“我有能力、有条件开展这项学术研究”，不是项目经理汇报进度和风险。按模板写成三方面加一句总结：

1. **在理论基础方面**：本课题依托哪些成熟理论（如运动学、可达性分析、采样规划），本课题要在此基础上**探索哪些尚未解决的问题**（写成学术问题，而不是工程任务）；本人通过文献调研和课程学习掌握了哪些理论（如实写，不编造课程名）。
2. **在技术储备方面**：本人已掌握或正在学习的软件、算法和工具（如 Unity 场景搭建、ROS 通信、开源规划库），它们能完成哪些基础计算，使研究精力集中在方法问题上。
3. **在研究条件方面**：实验室已有的工作积累与平台、设计资料、模型与计算设备、现场条件（“项目”二字前文已交代，这里不必再展开）。
4. 结尾一句：“综上所述，基于现有的理论基础、技术储备和研究条件，本课题的研究方案切实可行。”

禁止事项：
- **不引用文献**，不出现上标引用；
- 不写难度分级、人·月、降级方案、退路、“若做不出来则……”，这些放在内部的《可行性—难度—工作量评估表》中供用户和导师讨论，不进正文；
- 不写“由项目方提供数据”“待项目方确认”等项目协调口吻；
- 涉及用户本人学习、实践、设备条件的句子，用户未提供依据时**加黄色底纹**（Markdown 写作 `[句子]{.mark}`），交付时提醒用户核对后去掉底纹；
- 可用第一人称“我”（与参考模板一致），其余各部分仍统一用“本课题”。

## 四、本研究课题可能的创新之处

- 2–3 条，标题“4.1 拟提出一种……方法”/“拟改进一种……”；
- 每条 250–400 字：针对什么不足 → 核心思路（与已有方法的关键区别） → 预期带来什么；
- 慎用“首次”“国际领先”“彻底解决”；能说清“继承了什么、增加了什么、在哪个机制上不同”即可。

## 五、研究基础与工作条件（依据用户已完成的工作撰写，1.5.0 修订）

用户提供工作成果清单、过程记录或截图时，据此起草；没有提供时只给下面的提纲，由用户本人撰写。

> 5.1 研究工作积累基础：①文献与理论准备；②已完成的模型搭建、复现、仿真、实验（附图、附表）；③与课题相关的论文、专利、竞赛（如实填写）；
> 5.2 已具备的工作条件：①依托××项目（一句话即可）；②依托的实验室与软硬件条件；
> 5.3 尚缺少的条件与解决途径：只写确实缺少、且与后续研究直接有关的条件，每条写清解决途径。

口径要求：

- 只写已经完成、有过程材料的工作；未完成的（如通信联调、标定、精细碰撞模型）写进 5.3，不写成已完成；
- 数字与清单逐项一致（候选数、成功数、误差），不取整成更好看的数；用临时模型、替代参数或示意性设定得到的结果写明前提；
- 实验条件、软件平台的写法可参照学习模板中同类课题（数字孪生、仿真平台）的组织方式，措辞按本课题实际改写；
- 关键数据配三线表，场景截图配图并写清图中颜色或标记的含义；
- 需用户确认的句子用黄色底纹标出；用户在某一版中删改过的句子，后续版本原样保留。

## 1.3.0 补充（依据《存在的问题-V5》）

### 1.1 中写清研究边界

介绍完研究对象的结构和工作过程之后，用一段话写清研究范围，让专家知道工作量落在哪里：

> 整个……过程包含 A、B、C、D 等环节，流程与研究范围如图1-n所示。本课题的研究范围限定在 B：给定……，确定……。A 采用已有的……方法，只用于……；C 作为已知的……输入；D 不在研究范围之内。

研究范围**只用文字写**，不配“流程与研究范围”图（1.4.0：用户认为这种图有明显的 AI 味）。写法示例：

> 本研究在数字孪生模型中自动生成、筛选并验证作业位姿，研究对象限于拆卸阶段的作业位姿，机械臂进出窗口的路径规划只用来检验位姿能否到达，切割与拆装工艺作为已知的作业需求，搬运阶段不在研究范围之内。

### 1.2 凝练而不罗列

每个小节的骨架：

> 按照……，已有方法可分为 n 类。第一类……（思路一句）。代表工作 2–4 项（每项半句到一句）。这类方法……（优点），但……（局限）。第二类……。综上，……已有积累，但……（不足一、二、三）。因此，有必要……（引出自己的做法）。

- 一句话一项工作，用句号或逗号断开，不用分号串联，也不要一篇文献一段；
- 每一类必须有“优点”和“局限”各一句，局限要落到本课题的场景；
- 类别较多时配一张对比表（三线表）：方法类别｜代表工作｜优点｜局限。

### 1.3 与研究内容一一对应

研究内容有几项就写几条趋势，顺序一致。每条：趋势名称（从……走向……）→ 2–3 句依据（引 1–2 篇近两年文献）→ 末句落到这一趋势下还缺什么，自然收住，不写“据此，本课题拟……”“由此提出研究内容（n）”之类的桥接句。趋势总述句也不写“相关方向呈现以下四个发展趋势，四项研究内容分别由此提出”，直接写“（1）……”。四条写完后可用一两句短话收束。

### 2.1 开头的研究背景段

有的专家直接从第二部分看起。2.1 第一段写研究背景（250–400 字）：研究对象是什么、作业怎么进行、核心概念的定义、现在怎么做及问题、本研究要解决什么、不研究什么。然后再写特点、各项研究内容的关系和“具体研究内容如下：”。图2-1 较高（约 15 cm），放在四项研究内容之后，用一句“四项研究内容所针对的问题、采用的关键方法和预期结果之间的对应关系如图2-1所示。”引出，避免导语后出现大片空白。

### 表格与缩写

- 正文表格用三线表：顶线、底线 1.5 磅，栏目线 0.75 磅，无竖线；学校模板自带的信息表、工作计划表不改；
- 英文缩写首次出现写成“中文名称（English Full Name，ABBR）”，括号内用全角逗号；之后只用缩写或中文名。装置代号、软件产品名（如 Unity）不必展开。

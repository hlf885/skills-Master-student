# 07 语言规范：学术文风、去 AI 味、预判式写作

参考并改写自：hlf885/thesis-writing 的写作规范（保持作者声音、减少无效防御性措辞、按重要性分配篇幅）、op7418/Humanizer-zh（中文模板化表达检查）、Imbad0202/academic-research-skills 的 Writing Quality Check 与 Claim-Strength Ladder（论断强度不可悄悄改变）。

**原则：** 目标是写得准确、清楚、像作者本人，不是为了“骗过检测器”。不故意制造错别字、不随机替换同义词、不打乱逻辑。

## 一、开题报告的文风

- **正式、平实、具体**：主语明确、动词具体；少用“进行”“实现了……的提升”这类空壳结构；
- **“拟”字到位**：尚未完成的工作一律用“拟”“将”“计划”；已完成的前期工作才用“已”；
- **术语统一**：同一概念全文一个名称（如“数字孪生体/孪生体”定一个）；英文缩写首次出现给全称：“同时定位与地图构建（Simultaneous Localization and Mapping，SLAM）”；
- **称谓统一**：一律用“本课题”，不用“本文”“文中”“本研究”“我们”“我”（1.5.0；可行性分析中谈个人基础时可用“本人”，全篇一致）；改完后全文检索“本文”“文中”“本研究”；
- **数字与单位**：数字与单位之间是否空格按用户习惯全文统一（本仓库作者要求不空格，如“10mm”“0.41m”“3mm”），量和单位符合国家标准；
- **标点**：中文正文用全角标点；英文、公式、参考文献内用半角；不用“~”表示范围（用“至”）；正文少用双引号、破折号和箭头（见第十一节）。

## 二、去 AI 味：开题报告中最常见的模板化表达

逐条检查，确有问题才改；不是禁词表。

| 类型 | 典型表达 | 处理方式 |
| --- | --- | --- |
| 空洞开头 | “随着科学技术的飞速发展”“在当今时代背景下” | 换成有信息量的背景：具体政策、数据、事件 |
| 意义拔高 | “具有重大而深远的意义”“标志着……新时代”“填补了国内外空白” | 写清对谁、解决了什么、带来什么可检验的变化 |
| 高频空词 | 赋能、助力、深度融合、全方位、多维度、无缝、闭环（非控制意义）、至关重要、不可或缺 | 有具体含义的保留（如控制中的“闭环”），否则删或换具体动词 |
| 假对比 | “不仅是……更是……”“不是……而是……” | 两部分都有信息才保留 |
| 强凑三段 | 每处都是“三个方面”“三大挑战” | 有几点写几点；两点也可以 |
| 句尾拔高 | “……，彰显了……的巨大潜力”“为……奠定了坚实基础”（反复出现） | 全文“奠定坚实基础”类收尾不超过 2 次 |
| 进行+动词 | “对系统进行测试”“进行优化处理” | 直接写“测试系统”“优化” |
| “的”字堆叠 | “基于……的……的……的方法” | 调整语序或拆句 |
| 元叙述 | “本节将对……进行详细介绍”“下面让我们来看” | 直接开始说内容（章节导语一句即可） |
| 机械序数 | 每段都“首先、其次、最后” | 有先后顺序时保留；并列内容改为自然衔接 |
| 夸张形容 | “极具挑战性”“前所未有”“堪称” | 用事实说明难在哪里 |
| 套话收尾 | “综上所述，……具有广阔的应用前景”（每节都有） | 收尾写出本节结论或引出下一节的缺口 |

### 改写示例（教学用）

- 原：随着人工智能技术的飞速发展，机器人在各个领域发挥着越来越重要的作用，具有重大而深远的意义。
- 改：《“十四五”机器人产业发展规划》提出面向特殊环境加快研制特种机器人^[n]^。在核电站巡检等场景中，人员进入高辐射区域存在受照风险，机器人替代人工的需求迫切。

（改写只使用了可核实的事实；新增的政策出处必须经过核实再引用。）

## 三、论断强度：不可悄悄拔高或降低

- 等级：可能有助于 < 与……相关 < 能够预测 < 有助于 < 能够提升 < 能够保证/证明；
- 开题阶段没有实验结果，绝大多数论断停留在“拟”“预期”“有望”；
- 引用他人工作时，强度不超过原文（原文说“在仿真中验证”，不能写成“在实际中广泛应用”）；
- 慎用：“首次”“唯一”“完全解决”“国际领先”“填补空白”——除非有检索证据；
- 修改时也要保护必要的限定词（“在……条件下”“初步”“仿真中”），删掉它们等于改变了结论。

## 四、两种“防御性写作”

### 4.1 要删的：无效防御性措辞

- 反复自谦和预先辩解：“由于本人水平有限，难免存在不足”“本研究虽然不能完全……但……”（重复出现）；
- 假想敌式辩论：“有人可能会认为……但实际上……”且没有具体对象；
- 与论证无关的免责声明。

这些内容占篇幅、显得心虚。真实的限制条件、适用范围、风险与退路**必须保留**，并且集中写在方案与可行性部分。

### 4.2 要做的：预判式写作（答辩防御）

在写作时站到答辩专家的位置，提前把他们会问的问题在正文中答好：

| 专家常问 | 正文中应提前写清的位置 |
| --- | --- |
| 为什么非做不可？ | 1.1 立项必要性：痛点 + 后果 + 项目需求 |
| 和别人有什么不同？ | 1.2 每小节末的不足 + 第四部分创新点 |
| 研究内容之间什么关系？ | 2.1 导语与框图，内容条目中的“为后续……提供……” |
| 目标怎么检验？ | 2.2 目标的指标/验证方式 |
| 难点在哪里，凭什么能解决？ | 2.3 关键问题 + 3.2 理论分析中的拟改进点 |
| 做不出来怎么办？ | 3.3 可行性 + 评估表中的降级方案（可在正文中简述） |
| 工作量够不够、会不会太大？ | 研究内容 3–4 项 + 工作计划节点 |
| 平台和数据从哪来？ | 3.3 条件可行性（第五部分由用户写） |

写完后用这张表逐条自查：每个问题都能在正文中找到明确回答。

## 五、学术研究的口吻，而不是项目口吻

开题报告是学术研究计划。项目追求“设备能稳定运行”，学术研究要说明“要探索什么新问题、新方法，凭什么能回答”。

| 项目口吻（避免） | 学术口吻（采用） |
| --- | --- |
| 研究内容（2）难度最大，若计算量过大则降级为…… | 研究内容（2）拟探索……的表示方法，检验其能否……（风险评估留在内部评估表） |
| 完整模型和数据将由项目方提供，协作臂型号待确认 | 依托项目的设计资料与三维模型建立孪生模型 |
| 已有成熟方案，本课题主要做集成 | 已有方法解决了……，但……尚未解决，本课题拟提出…… |

**背景与研究边界**：立题依据中，依托项目的作业方式、设备控制方式（如遥操作）等只作铺垫，篇幅不应超过课题真正研究的对象；课题不做的内容通过叙述重心来弱化，少提或不提，不写“需要说明的是，××不是本课题的研究内容”这类声明句。

**依托项目只交代一次**：1.1 中写明依托项目即可，后文不反复出现“项目”“项目方”“项目要求”“按项目工艺调整”。“本课题”全文控制在 4–12 次。

## 七、像师兄师姐那样自然叙述（V3 审阅意见汇总）

开题报告是写给专家看的研究计划，不是讲稿、不是项目计划书，也不是写作过程的记录。下面这些句子都要删掉或改写：

| 类型 | 原句（问题示例） | 改法 |
| --- | --- | --- |
| 讲稿式导读 | “本课题涉及……四个方面。第一部分说明……第二部分……后两部分对应本课题的核心方法。” | “……涉及A、B、C、D四个方面，相关研究现状如下。”或直接进入 1.2.1 |
| 讲稿式过渡 | “下面分别说明四项研究内容各自针对的问题和要得到的结果。” | 删除；导语末句写“具体研究内容如下，如图2-1所示：” |
| 对照说明 | “本节对应关键问题（3）的基础部分，目标是建立可供规划算法直接调用的孪生模型。” | 删除，直接写研究对象和建模理由 |
| 思考过程/聊天内容 | “上述目标中，10Hz依据……确定；其余目标以对比方法为基准，具体数值在前期验证后结合项目要求确定……确认后的口径在中期检查时一并说明。” | 整段删除；指标来源属于和导师、用户讨论的内容 |
| 自我设限 | “条件具备时开展虚实同步验证和现场试验”“现场试验在设备与场地条件具备并经项目方许可后进行” | “在仿真实验的基础上开展虚实联合验证：首先……然后……” |
| 预先留退路 | “偏差数据不足时，先按项目定位精度要求设定”“第一阶段拟按照……具体条件按项目工艺调整” | 删除，或把必要的工况假设写成平实陈述：“作业时主臂保持静止，两条协作臂按工序依次动作” |
| 范围声明 | “本节建模指运动学、碰撞和任务建模，不重新制作三维机械模型。” | 删除；在正文里写清建了什么，读者自然知道没做什么 |
| 结论保留 | “以上为拟创新点，最终表述将依据对比实验和消融实验的结果确定。” | 删除；“拟提出”已经表明是计划 |

自检方法：通读全文时问自己，这句话是在**讲研究**，还是在**向读者解释这份报告怎么组织、为什么这样写、以后会怎样调整**？后者一律删掉。`scripts/check_proposal.py` 会列出常见的元叙述、自我设限句和“本课题”“项目”的出现次数。

## 六、学习用户的写作风格

如果用户提供了本人写过的文字（小论文、课程报告），从中提取：句长习惯、常用连接词、术语偏好、引用句式、段落长度。写作时作为**软约束**；学科规范和学校要求优先。不把样本中的事实、数据搬进开题报告。

## 八、人称代词、缩写与公式字体（1.3.0 新增）

- **不用人称代词**：我、你、他、她、它、我们、咱们，以及“我国”和作代词用的“其”。改法：省略主语（“已系统阅读了……”）、重复名词（“该图谱与……”“候选对作业的覆盖关系”）、“我国”改“国家”或“中国”。“其中、其余、其他”不算；学校模板栏目说明里的原文不改；
- 第三部分可行性分析以学生视角写，但同样不出现“我”：用“开题准备阶段已……”“目前已……”“在研期间有机会……”；
- 修改后用程序统计全文中上述字词的出现次数，写入修改记录表；
- **缩写**：见 `02-section-guide.md` 1.3.0 补充；
- **公式字体**：默认对标学习模板（变量斜体）。用户明确要求“不倾斜、不加粗”时，公式中的字母、数字、希腊字母全部设为 Times New Roman 正体；运算符同样设为 Times New Roman（OMML 中加 `m:nor` 并指定 `w:rFonts`）。这样运算符两侧不再自动加间距，`\min_{s} g` 之类要在 LaTeX 中写成 `\min_{s}\,g`，公式内不用分号分隔（改用逗号加 `\qquad`）。在修改记录表中说明。

## 九、依托表述、分号与衔接套话（1.4.0 新增，依据《存在的问题-V6》）

- **依托表述**：写“依托××项目，以……为研究背景”。不写“本课题依托实验室承担的××项目”“依托课题组承担的……”，“实验室承担”“课题组承担”读起来像项目汇报。改完后全文搜索“承担”自查；
- **分号**：中文学术写作里分号常被滥用成“一长串并列”。除“式中，A 为……；B 为……”的符号说明外，正文、表格、图中文字都用句号或逗号。并列内容多时拆成几句，或用“一是……二是……”；
- **衔接套话**：以下句子删去或改写，直接进入内容。

| 不要这样写 | 可以这样写 |
|---|---|
| 结合上述研究现状，相关方向呈现以下四个发展趋势，四项研究内容分别由此提出： | （直接写）（1）孪生模型从状态映射走向决策支撑。…… |
| ……。据此，本课题拟研究…… | ……。（这一条趋势的末句落在“还缺什么”，研究内容在第二部分写） |
| 本课题依托实验室承担的HL-3偏滤器远程维护项目 | 依托HL-3偏滤器远程维护项目，以偏滤器拆卸作业为研究背景 |
| ……，并据此反演得到…… | ……，在此基础上反演得到…… |

- 修改后用 `check_proposal.py` 统计分号和上述短语，结果写入修改记录表。

## 十、书面化表述与版面（1.5.0 新增，依据《存在的问题-V7》）

**书面化**：口语化的问句式表述、绝对化判断改成书面陈述，判断要有文献支撑。

| 不要这样写 | 可以这样写 |
|---|---|
| 主臂停在什么位置、以什么构型停住，直接决定两条协作臂能否完成作业。文中把这一位姿称为…… | 主臂末端的停靠位置及实现该位置的主臂构型，决定了两条协作臂能否完成拆卸作业。本课题将这一位姿称为…… |
| 远程维护中，操作人员看不到腔内的全貌，虚拟模型原本就是了解腔内情况、预演作业过程的主要途径。 | 远程维护过程中，操作人员无法直接观察腔内全貌，维护方案通常需要先在虚拟环境中预演和检验[n]。 |

**版面**：用户说“留白过多”时按以下顺序排查，改完在 Word 中复查（LibreOffice 与 Word 分页不同，以 Word 为准；Word 显示比例调到 30% 左右可一屏看十几页）。

1. 学校模板的大表格行常设最小行高（如整页高），内容不满一页时留下大片空白：去掉 `w:trHeight` 大于约 3000 twip 的行高；
2. 工作计划表前的强制分页：删去分页符；如果计划表在单独的节里，把该节改为连续分节（`w:type="continuous"`），并让“学位论文工作计划”标题与表格同页（`keepNext`）；
3. 图片与图题分在两页：图片段落设 `keepNext`；
4. 大图放不下导致上一页留白：按版面缩小（流程图宽度 11–12.5cm，竖长的实物图 4–6cm），或把图与其后一段文字对调（引用句仍在图之前）；
5. 表格需要跨页时，表头行设为跨页重复（`w:tblHeader`）。

## 十一、引号、破折号与箭头（1.6.0 新增，依据聊天中的修改意见）

用户认为成段出现的双引号、破折号、箭头是明显的 AI 痕迹：

- 正文不用破折号（——）引出解释，改成逗号加完整的句子，或另起一句；
- 双引号只在首次给出术语定义、引用文件名称时使用，同一个词不反复加引号；
- 正文不用箭头（→）表示流程，改成“先……再……”“由……得到……”；图中的箭头不受此限；
- 页码范围、英文题名中的连接号统一用半角连字符“-”，时间范围写“2026.10-2026.11”；
- 修改后用 `check_proposal.py` 统计引号、破折号、箭头的数量，写入修改记录表。

# 11 论证主线：从题目出发，层层递进，首尾闭环（1.6.0 新增）

来源：本仓库作者开题报告《基于数字孪生的受限空间机械臂作业位姿优化方法研究》V8–V11 的立题依据。作者认为这一部分“整体围绕题目，逐步层层递进展开”。本文件把它的写法拆成可复用的步骤，换成任何题目都能照做。文中聚变装置的内容只用来说明写法，不能搬进别人的报告；每个人的困难、不足、趋势都要从自己的对象和自己检索核实的文献中得出。

## 一、总思路：整份报告只讲一条链

```
题目 → 1.1 为什么要做 → 1.2 别人做到哪一步、还差什么 → 1.3 往哪里走
     → 2.1 本课题做什么 → 2.3 难在哪里 → 三 怎么做 → 四 新在哪里 → 五 已有什么基础 → 回到题目
```

每一环只接上一环交来的东西，再交给下一环一样东西。读者在任何一段停下，都应能说出“这一段之所以出现，是因为前面讲了……，它要为后面的……做准备”。说不出这句话的段落，要么删，要么挪。

贯穿全文的三个约束：

- **题目中的每个关键词都有落点**：在 1.1 被引出，在 1.2 有对应的小节或类别，在 1.3 有对应的趋势，在 2.1 有对应的研究内容；
- **同一件事全文一个名字**：1.1 中定义的核心概念（如“作业位姿”）从定义处起不换说法，题目中的对象词（如“机械臂”）与正文术语的对应关系也在定义处交代清楚；
- **前后的数目对得上**：1.1 的困难、1.2 的不足、1.3 的趋势、2.1 的研究内容、2.3 的关键问题之间能一一或多对一连线，没有落空的一项。

## 二、动笔前先做两张表

### 2.1 题目拆解表

把题目拆成四类词，逐个写出它准备在哪里落地：

| 类别 | 问自己 | 作者题目中的词 | 在报告中的落点 |
| --- | --- | --- | --- |
| 研究对象与场景 | 研究什么东西，在什么环境里 | 受限空间、机械臂 | 1.1 第3–5段，1.2.1，1.2.3 第三条不足 |
| 核心概念 | 要确定或改进的那个量是什么 | 作业位姿 | 1.1 第5段定义，1.2.3，2.1 各项 |
| 方法或手段 | 靠什么来做 | 数字孪生 | 1.1 第7段，1.2.2，1.3（1），研究内容（1）（4） |
| 目标动作 | 对这个量做什么 | 优化方法 | 1.1 困难段，1.2.3、1.2.4，研究内容（2）（3） |

规则：

- 任何一个词在“落点”一栏写不出三处以上，说明题目和内容对不上，先改题目或改内容，再动笔；
- 题目受字数限制（如不超过 23 字）而删掉的修饰词，要在 1.1 的困难段中出现；
- 导师要求体现的方法关键词（如数字孪生）不只出现在题目里，还要成为 1.2 的一个小节、1.3 的一条趋势和至少一项研究内容。

### 2.2 论证主线表（最重要）

每一行对应一项研究内容，从左到右是这项内容在全文中的来龙去脉。作者报告的主线表如下：

| 研究内容 | 1.1 困难（场景事实） | 1.2 不足（文献事实） | 1.3 趋势 | 2.3 关键问题 | 3.2 方法 | 四 创新点 | 五 前期数据 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| （1）面向作业位姿规划的数字孪生建模 | 拆卸中相邻部件状态和设备实际位置会变，事先确定的位姿未必可用 | 1.2.2：孪生模型应包含哪些信息才能支撑决策、状态变化后结果如何更新、虚实偏差如何进入安全裕度，讨论较少 | （1）孪生模型从状态映射走向决策支撑 | （3） | 3.2.1 | 无（作为基础） | 临时模型、逆解、干涉检测 |
| （2）双臂联合作业能力图构建与作业位姿反演 | 一臂执行、一臂配合，工具沿规定方向接近再退出，只查目标点可达说明不了作业可完成 | 1.2.3 不足一、二：以单臂、目标点可达为判据，双臂以各臂可达性为依据，未计入分工与干涉 | （2）从单臂点级可达走向多臂作业能力 | （1） | 3.2.2 | 4.1 | 相距约 10cm 的两点双臂协同，常规求解始终有 3–4 处干涉 |
| （3）孪生场景驱动的作业位姿检索与筛选 | 腔内间隙小、人工试凑耗时，换一次位姿耗时长 | 1.2.3 不足三与 1.2.4：基座是冗余主臂在腔内的末端；场景多视为静态，检查结果不能复用 | （3）从串行走向分层联合 | （2）（3） | 3.2.3 | 4.2 | 450 个候选中末端可达 308 个，无干涉仅 30 个 |
| （4）孪生仿真与虚实联合验证 | 设计模型与实际状态有偏差 | 1.2.1：虚拟环境多承担事后检查；1.2.2：模型一致性决定能否用于决策 | （4）从单纯仿真走向虚实联合 | （3） | 3.2.4 | 无（验证） | 无 |

填表规则：

1. **先填“困难”和“不足”两列**，它们是事实。研究内容由这两列推出来，不是先定好内容再回头找理由；
2. “困难”写场景事实（空间多小、作业怎么分工、换位多慢、状态会变），“不足”写文献事实（已有方法以什么为判据、没有计入什么），两者不能互相代替；
3. 一行里出现空格就是断链：补场景事实、补文献，或者删掉这一项内容；
4. 关键问题是困难的“机理化”说法：困难讲现象，关键问题讲为什么难（耦合、高维、代价、不确定性）；
5. 第五部分的前期数据最好落到某一行，用数据说明这一行的必要性；
6. 主线表不写进报告，随修改记录一起交给用户，答辩前用它准备“为什么做这一项”的回答。

## 三、1.1 研究目的及意义：八段漏斗

由远及近、由大到小，每段只做一件事，最后一段落回题目。全节约 1300–2000 字。

| 段 | 这一段的任务 | 交给下一段的东西 | 作者报告中的首句 | 换成别的题目怎么写 |
| --- | --- | --- | --- | --- |
| ① 国家与行业 | 用政策、法规、装置或行业数据说明领域重要，落到一个具体需求 | 一项必须被满足的需求 | 受控核聚变是国家能源科技发展的长期方向。 | 从规划、法规或数据落到“××工作只能／必须由××完成” |
| ② 需求的普遍性 | 国内外同类系统都把这件事当成必要条件 | 这是共性问题 | 远程维护因此成为聚变装置长期运行的必要条件。 | 列 2–3 个国内外同类系统的做法，引近年文献 |
| ③ 依托项目与研究对象 | “依托××项目，以……为研究背景”，对象结构、作业过程、关键数字，配图 | 读者看清对象的样子和工作过程 | 依托HL-3偏滤器远程维护项目，以偏滤器拆卸作业为研究背景。 | 结构 → 流程 → 具体数字（自由度、部件数、尺寸） → 图 |
| ④ 研究边界 | 整个过程拆成几个问题，本课题只做哪一个，其余怎么处理 | 一个被圈定的问题 | 在这一维护过程中，……分别属于不同的研究问题。 | “A 采用已有方法，只用于……，B 作为已知输入，C 不在研究范围之内”，只用文字，不配图 |
| ⑤ 核心概念与困难 | 一句话说这个量为什么关键，再定义题目中的核心概念，接着写确定它的困难 | 3–4 个来自场景事实的困难 | 主臂末端的停靠位置及实现该位置的主臂构型，决定了两条协作臂能否完成拆卸作业。 | “本课题将……称为……”。困难用自然段叙述，不编号，每个困难一句事实加一句后果 |
| ⑥ 现有方法为何不能直接用 | 一段话点出已有研究的总体假设与本对象的差别 | “现有方法不够”的判断，留给 1.2 展开证实 | 机器人基座位姿选择已有较多研究，但大多面向…… | “……已有较多研究，但大多面向／假设……，而本对象……，这些方法难以直接使用” |
| ⑦ 方法手段为何合适 | 引出题目中的方法关键词：是什么，这个场景为什么需要它，用上之后能变成什么 | 一条方法路线（全文的愿景） | 数字孪生通过虚拟模型与物理实体之间的数据交互…… | 定义一句（引近年综述） → 场景为什么天然需要它 → “如果……，就能从……扩展为……” |
| ⑧ 因此与意义 | “因此，以……为研究对象，开展＋题目全称”，理论意义一句，工程意义一句 | 题目本身 | 因此，以主臂、双臂协作机器人、工具和偏滤器组成的系统为研究对象，开展基于数字孪生的受限空间机械臂作业位姿优化方法研究…… | 理论意义写方法层面的贡献能推广到哪类问题，工程意义写对依托对象的直接用处，再写能推广到哪里 |

要点：

- ⑤ 的每个困难都要能在主线表中找到所在的行；⑥ 的判断要在 1.2 中被逐类证实；⑦ 中“如果……就能……”是全文的愿景，2.1 和图2-1 要兑现它；
- 段与段之间靠承接上一段内容的词衔接（“因此”“在这一维护过程中”“确定作业位姿存在以下困难”），不靠“下面介绍”；
- ③ 的数字要具体、要与第五部分和第三部分一致；
- 1.1 不写的内容：方案细节、算法名、指标数值（指标放 2.2）、与同组同学的分工和比较。

## 四、1.2 国内外研究现状：先排小节，再排类别

### 4.1 小节怎么定、怎么排

1.2 开头一句话列出要讲的几个方面，方面数等于小节数。小节一般按四种角色由外到内排列：

| 角色 | 讲什么 | 作者报告 |
| --- | --- | --- |
| 应用领域 | 同类对象或行业现在怎么完成这件事 | 1.2.1 聚变装置远程维护作业规划研究现状 |
| 方法载体 | 题目中的方法关键词在相关领域的研究 | 1.2.2 面向机器人作业的数字孪生研究现状 |
| 核心技术 | 核心概念对应的那一类算法 | 1.2.3 机器人基座位姿规划研究现状 |
| 支撑技术 | 让核心技术落地还缺的环节 | 1.2.4 作业位姿运动可行性检查与方案更新研究现状 |

题目里没有方法关键词时，可把核心技术拆成两个小节。小节一般 3–5 个，每个小节至少对应一项研究内容，小节标题用题目和研究内容里的词。

### 4.2 小节内部：分类标准、类别递进、本对象定位、小结

1. **开头一句给出分类标准**：“按照……，已有方法大体可分为 n 类”（或 n 个层次、n 种做法）。标准要与本课题的核心问题有关，分完类后本课题的位置自然清楚。作者按“设备作业位置的确定方式”给远程维护分类，按“对作业能力的描述方式”给基座规划分类，按“孪生模型在作业中承担的角色”把数字孪生分成状态映射、仿真预演、决策支撑三个层次；
2. **类别按递进顺序排**：由简单到复杂、由单一到综合、由离线到在线、由静态到动态。前一类的局限正好是后一类要解决的问题，读到最后一类时，读者已经站在本课题门口；
3. **每类的写法固定**：思路一句 → 代表工作 2–4 项（一句一项，带引用） → “这类方法……（优点），但……（局限）”。局限用本对象的语言写（“只反映单一构型，不能说明一段作业能否完成”），不写“效果有待提高”；
4. **加一句本对象定位**：在相关类别之后写“××属于第二类，……的问题也就更加突出”。这一句把文献拉回题目，是“围绕题目”的关键；
5. **小节小结**：以“总体来看／可以看出／综合来看”开头，先一句肯定已有积累，再写不足。不足多于一条时用“一是……二是……三是……”，每条写成本对象场景下的缺口，并能对上主线表的一行；
6. 类别多时配一张三线对比表（方法类别｜代表工作｜优点｜局限），配一两幅不含外文文字的文献原图。

### 4.3 小节之间

- 前一小节的不足引出后一小节的话题。作者报告中：1.2.1 结尾“由模型自动给出作业位姿并随场景更新的规划方法还很少见” → 1.2.2 讨论孪生模型能否支撑决策 → 1.2.3 讨论作业位姿本身怎么决策 → 1.2.4 讨论决策结果怎么检查和随场景更新；
- 不用“下面介绍……”过渡，靠小节标题和首句的内容衔接。

## 五、1.3 发展趋势：一条趋势对一项内容

- 条数与研究内容相同，顺序一致；
- 标题写成“××从 A 走向 B”，A 取自 1.2 小结中的现状，B 是方向；
- 正文：2–3 句近两年文献依据 → 一句“不过／但……尚未……”的缺口 → 末句落到本对象（“……同样需要……”“……是其中尚未解决的一环”“……可以朝这一方向发展”），自然收住，不写“据此，本课题拟……”；
- 各条趋势之后，用一句话把它们串起来，句中出现题目中的方法关键词和对象，相当于把题目换一种说法再说一遍。作者写的是：“以数字孪生模型为载体，把双臂作业能力的表示、主臂腔内可实现性的判断、场景变化后的方案更新和虚实联合验证结合起来，是解决聚变装置受限空间中机械臂作业位姿确定问题的可行途径。”这一句就是闭环的扣子。

## 六、写完后的六项闭环检查

1. **首句串读**：把 1.1、1.2 各小节、1.3 每段的第一句按顺序抄出连读，应是一篇通顺的摘要。某一句接不上，说明那一段放错了位置或缺少承接。`scripts/check_logic_chain.py` 可自动抽出首句；
2. **关键词落点**：题目中的每个关键词在 1.1、1.2、1.3、2.1 都出现，某一节为 0 就补（脚本可统计）；
3. **主线表无空格**：主线表的每一格都能在正文中指到具体句子；
4. **删段测试**：设想删去某一段，后文是否有地方失去来源。删掉后什么都不缺的段落不在链上，压缩或删除；
5. **反向追溯**：从每个创新点出发，倒查 2.3 关键问题 → 1.2 不足 → 1.1 困难，三步都能找到原句；
6. **因果与口径一致**：同一事实在 1.1、1.2、2.1、3.2、第五部分的数字和说法一致，因果方向不颠倒，依据文献写出的判断不超出原文（见 `04-citation-gbt7714.md` 第七节）。

## 七、换一个题目怎么用

以下示例只示范结构，内容需按实际课题检索、核实后重写。

**示例：“基于多源信息融合的狭长管廊巡检机器人定位方法研究”**

- 题目拆解：对象与场景为狭长管廊、巡检机器人；核心概念为定位（可定义为带可信程度的位姿估计）；方法为多源信息融合；目标动作为定位方法研究。
- 1.1 八段：① 城市地下综合管廊的建设与运维要求，落到“长距离日常巡检需要由机器人完成” → ② 国内外隧道、管廊机器人巡检实践 → ③ 依托××项目，机器人结构、传感器配置、巡检流程、管廊长度 → ④ 边界：巡检路径规划与缺陷识别作为已有功能，只研究定位 → ⑤ 定义“定位可信度”，困难：结构重复、特征稀疏、长距离累积误差、卫星信号不可用 → ⑥ 已有激光与视觉定位多面向特征丰富的环境 → ⑦ 多源融合为何适合，用上后能从“给出位置”扩展为“给出位置及其可信程度” → ⑧ 因此＋题目全称＋理论意义与工程意义。
- 1.2 小节：应用领域（管廊与隧道巡检机器人） → 方法载体（多源信息融合定位） → 核心技术（退化环境下的定位） → 支撑技术（定位可信度评估与重定位）。
- 1.3 四条趋势与四项研究内容一一对应，最后一句把“多源融合”和“狭长管廊定位”放在同一句里收住。

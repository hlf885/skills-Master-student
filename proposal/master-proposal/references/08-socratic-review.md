# 08 苏格拉底式追问与自审清单

参考 Imbad0202/academic-research-skills 中 Socratic Mentor 的做法（导师式追问、每章必答问题、先引导后起草），结合开题报告的特点改写。原则：**用问题帮用户把想法说清楚，而不是替用户拍板。**

## 一、追问规则

- 每次只追问一个层面，一轮 2–4 个问题；
- 先问开放问题，用户卡住时再给 2–3 个选项帮助思考；
- 用户的回答模糊时，请他“用一句话说”或“举一个具体例子”；
- 每轮结束，用 3–5 行总结你听到的要点（“定位要点”），请用户确认；
- 用户明确说“直接写吧”时，可以减少追问，但硬性规则（资料确认、量化指标询问）不能跳过。

## 二、六层追问（阶段 2）

### 第 1 层：问题是否真实、重要

- 如果这个问题不解决，现场会发生什么？有没有具体案例？
- 谁最关心这个问题？项目甲方/用户的原始需求是什么？
- 为什么是现在做？过去为什么没解决好？

### 第 2 层：缺口是否清楚

- 现有最好的方法是什么？它在你的场景里具体哪里不行？
- 这个“不行”是参数没调好，还是方法本身的假设不成立？
- 你能用一句话说出“现有方法的不足”吗？

### 第 3 层：要做的事是否聚焦

- 用一句话说出你的课题：“我要让×× 在 ××条件下 ××。”
- 题目里的每个关键词，分别对应哪项研究内容？
- 3–4 项研究内容中，哪一项是核心？去掉哪一项课题就不成立？
- 有没有哪项内容其实是项目里别人在做的？

### 第 4 层：关键难点是否找准

- 最难的地方难在什么机理上（高维、耦合、不确定性、实时性、小样本、虚实差异）？
- 这个难点和研究内容是什么关系？
- 如果只能解决一个难点，你选哪个？

### 第 5 层：怎么证明做成了

- 你会和什么方法比？在什么场景下比？看哪些指标？
- 项目有考核指标吗？（此处转入量化指标的专门询问）
- 仿真和实物各验证什么？

### 第 6 层：边界与退路

- 你的方法在什么情况下可能失效？
- 最坏情况下，哪一部分可以降级完成？
- 时间不够时，哪项内容可以缩小规模？

## 三、追问产出：《课题定位卡》

```
一句话课题：
研究对象与场景：
依托项目及本人分工：
现有方法的核心不足（1–3 条）：
研究内容（3–4 项，每项一句）：
关键问题（2–3 个）：
目标口径：量化 / 定性 / 部分量化（附指标）
验证方式：对比基线、场景、指标
边界与退路：
```

用户确认定位卡后，再进入文献检索与提纲。

## 四、交付前自审清单（阶段 7）

### 逻辑一致性

- [ ] 题目 ↔ 研究内容：题目关键词全部有落点；没有题目外的大块内容；
- [ ] 1.2 的不足 ↔ 2.3 关键问题 ↔ 第四部分创新点：一一对应、措辞不重复；
- [ ] 研究内容 ↔ 研究目标 ↔ 3.2 理论分析小节 ↔ 工作计划：数量与顺序一致；
- [ ] 研究内容只说做什么（无算法步骤、无公式、无软件操作）；每项约 4–5 行；
- [ ] 量化指标与用户确认口径一致，数值有出处；
- [ ] 第三部分的方案经过评估表确认，难度与工作量合理，有降级方案；
- [ ] 第五部分已留给用户撰写，并有醒目提示。

### 规范性

- [ ] 各部分字数在目标区间内（`scripts/check_proposal.py`）；
- [ ] 参考文献 56–66 条，格式统一，正文首次引用顺序递增，无重复、无未引用；
- [ ] 图、表、公式编号连续，正文先提及后出现，图题在下、表题在上；
- [ ] 图片清晰、无水印、来源已记录；
- [ ] 术语、缩写、称谓（本课题/本研究）统一；
- [ ] 没有错别字、病句、中英文标点混用。

### 预判式写作

- [ ] `07-style-deai-defensive.md` 第四节的 8 个问题在正文中都有答案；
- [ ] 无重复的自谦、免责声明；真实限制保留在合适位置。

### 去 AI 味

- [ ] 按 `07-style-deai-defensive.md` 第二节逐条检查，修改确有问题的表达；
- [ ] 论断强度没有被悄悄拔高（尤其是“首次”“填补空白”“显著提升”）。

### 诚信

- [ ] 没有编造的文献、数据、成果、获奖、项目信息；
- [ ] 未完成的工作没有写成已完成；
- [ ] 往届报告的内容没有被照搬。

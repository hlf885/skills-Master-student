# 05 研究方案：先评估、再设计；Visio 作图；MathType 公式；无水印图片

## 一、先评估：《可行性—难度—工作量评估表》

写第三部分之前，先对每项研究内容的候选方案做评估，并把表格给用户确认。没有经过评估的方案不写进开题报告。

| 研究内容 | 候选方案（主/备） | 理论可行性 | 技术可行性（工具链、开源基础、已有复现） | 条件可行性（平台、数据、经费、时间） | 难度（1–5）与难点 | 工作量估计（人·月） | 主要风险 | 退路/降级方案 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| （1）…… | 主：…… 备：…… | | | | | | | |

评估规则：
- **难度**：1=有成熟开源实现可直接使用；2=需要适配；3=需要较大改进；4=需要提出新方法；5=无先例、风险高。硕士课题中，难度 4–5 的内容最多一项，并且必须有降级方案；
- **工作量**：总量与培养周期匹配（开题到中期约 10–12 个月，中期到送审约 6–8 个月）。超出时与用户讨论删减或合并研究内容；
- **依赖关系**：标出“必须先完成才能开始”的前后依赖，用于工作计划排期；
- 评估结论用两三句话写给用户：哪项最难、哪项最可能拖期、建议怎样调整。

用户认可后，按评估结果写 3.1 技术路线、3.2 理论分析、3.3 可行性分析。3.3 中的论述应与评估表一致，不夸大。

## 二、技术路线与理论分析的写法

- **技术路线图（图3-1）**：从“问题分析”到“实验验证”，每个研究内容一条主线，标出输入/输出与反馈回路；右侧“阶段成果”只写研究成果（模型、候选集合、方案、实验结论），不写学术论文、学位论文、专利；
- **理论分析**：每个 3.2.x 写清“模型—原理—拟改进点—输出”，公式只放必要的：问题定义、系统模型、优化目标/代价函数、关键更新公式、评价指标；
- 用“拟采用”“拟改进”“拟构建”，不写“已实现”；
- 每个公式后有“式中，……”逐一解释符号和单位；符号在全文中含义一致；
- 方案中出现的每个评价指标，都要在 2.2 研究目标或实验验证中有对应。

## 三、Visio 作图流程

### 3.1 作图前

1. 对用户说：“接下来需要作图。请先打开 Microsoft Visio（新建空白绘图），并打开 Word 文档，告诉我已经打开。”
2. 等用户确认后再继续。

### 3.2 图的规格（先在对话中给出，用户确认）

每张图先写一份规格：图号、图题、用途、节点（文字、层级）、连线（方向、标签）、分组框、配色、字号。全文统一视觉风格：

- 字体：中文宋体、英文 Times New Roman；图内文字 9–10.5 pt；
- 线条：0.75–1 pt 实线，箭头统一；分组框用虚线；
- 配色（参考模板，全文统一）：标题框与目标框用浅蓝填充 RGB(221,235,247) + 蓝色边框 RGB(46,117,182)；问题、内容、方法框用浅橙填充 RGB(251,229,214) + 橙色边框 RGB(237,125,49)；分层虚线框用黄色 RGB(255,192,0) 和蓝色 RGB(0,112,192) 交替；箭头用深蓝 RGB(47,85,151)；层名用深蓝加粗；**重点词用红色 RGB(255,0,0)**。不用深色实底白字的大色块；同一含义同一颜色；
- 版面：宽度不超过版心（约 15 cm），导出 EMF/SVG（矢量）或 300 dpi 以上 PNG；
- 图题在图下方、表题在表上方，居中，黑体五号，图号与标题之间用**一个半角空格**：“图2-1 研究内容框图”“表3-1 对比方法设置”。不用全角空格，全角空格在 Word 中常显示为方框；
- 常用图：研究内容框图（图2-1）、技术路线图（图3-1）、系统总体结构图、算法流程图、模型结构图。

### 3.3 绘制方式（按可用能力选择）

- **方式 A：电脑操控。** 若当前环境可以操控用户电脑（如 Claude Cowork 的电脑使用能力），申请 Visio 与 Word 的操作权限后，直接在 Visio 中按规格绘制，保存 .vsdx，并导出 EMF 插入 Word。
- **方式 B：Visio 宏一键生成（推荐的通用方式）。** 用 `scripts/visio_macro.py` 把图规格（JSON，示例见 `assets/figure-spec-example.json`）转成 VBA 宏：
  ```bash
  python scripts/visio_macro.py assets/figure-spec-example.json -o fig2-1.bas
  ```
  用户在 Visio 中按 `Alt+F11` 打开 VBA 编辑器 → 文件 → 导入 `fig2-1.bas` → 运行 `DrawFigure`，即可得到**完全可编辑**的 Visio 图，再微调和导出。
  图规格支持：节点 `fill`/`stroke`/`font_color`（填充、边框、文字颜色）、`red`（需要标红的重点词列表，宏中逐个着色）、`no_border`（层名等纯文字标签）、`font_pt`；分组框 `stroke`（虚线颜色）；连线 `color`。加 `--png fig.png` 可直接渲染预览图插入 Word，与宏生成的图版式一致。分层研究内容框图示例：`assets/figure-spec-research-content.json`。
- **方式 C：用户手绘。** 提供图规格和草图（SVG/PNG），用户在 Visio 中照着绘制。

无论哪种方式，最终交付 `.vsdx` 源文件（或宏）+ 导出的矢量图。

## 四、MathType 公式流程

1. 写公式前对用户说：“请在 Word 中确认 MathType 选项卡可用（已安装并加载 MathType）。”
2. 稿件中公式先以 Word 原生公式（或 LaTeX）写入：`scripts/build_docx.py` 会把 Markdown 中的 `$$...$$` 转为 Word 公式；
3. 用户在 Word 中：MathType 选项卡 → **Convert Equations（转换公式）** → 源类型勾选“Microsoft Word 公式（Office 2007 及以后）”→ 目标选“MathType equations (OLE objects)” → 全部转换。若该选项在用户的 MathType 版本中不可用，改用 `build_docx.py --latex-text` 生成保留 `$$…$$` LaTeX 文本的版本，再在 Word 中选中 LaTeX 文本，按 MathType 的 **Toggle TeX**（默认快捷键 `Alt+\`）逐个转换；
4. 编号：使用 MathType 的“Insert Number/右编号”或表格法（公式居中、编号右对齐），格式统一为 (3-1)；章节变化时重置；
5. 若需要逐个录入：提供每个公式的 LaTeX，用户在 MathType 编辑窗口中直接粘贴 LaTeX（MathType 会自动识别转换）；
6. 若可以操控电脑，也可以直接在 MathType 中录入并检查。

公式书写规范（对标学习模板中的 MathType 公式）：
- 字体 Times New Roman、五号；变量斜体，数字、函数名（min、max、FK）、单位、下标中的文字说明（twin、safe）和大写希腊字母正体；**一律不加粗**，矩阵、向量也用普通斜体字母；
- 不用左上标写法 `{}^{W}T_{F}`（Word 中会在空底数处显示虚线方框），坐标变换写成 $T_{F}^{W}$；不用花体 `\mathcal`、不用尖括号 `\langle\rangle`，元组用圆括号；
- 带编号的公式按独立公式排版：公式居中、分式为全尺寸、求和与连乘的上下限在符号上下方，编号 (3-1) 右对齐（`build_docx.py` 自动生成无边框三栏表格）；
- 同一符号全文只表示一个量，避免同一字母既表示坐标系又表示集合；
- 不要把公式截图当公式。

## 五、研究资料图片的获取与无水印核查

**插图方式（硬性）**：项目资料、文献或网页中的图片，一律**取原始图片文件逐张插入** Word（从 docx 的 `word/media`、PDF 原图或网页原图获取），不得把几张图截屏拼成一张，也不得放大缩小后重新保存，否则图片失真模糊。多子图并排时，用无边框表格放置原图，子图题“(a) ……”“(b) ……”写成文字，总图题写在表格下方；插入后核对嵌入文件与原图逐字节一致。

1. **优先级**：用户自有/课题组自拍图片 > 官方新闻稿或媒体资料包（press kit）> 开放许可图片（Wikimedia Commons 等，遵守许可并署名）> 学术论文原图（在图题后标注引用编号）；
2. **检索**：用所有可用途径（网页检索、浏览器、官方网站、论文全文）查找**清晰（短边 ≥ 800 像素）**的原图，优先下载原始大图而不是缩略图；
3. **核查**：逐张放大检查四角、中心、背景、子图内部有无水印、平台标识、截图界面残留、半透明文字；有水印的图片**不用**，也**不擦除**他人的水印或署名，改找原始无水印版本或自行重绘示意图；
4. **记录**：建立《图片来源表》（图号｜来源 URL/文献编号｜许可/授权说明｜分辨率｜水印核查结果），随稿交付；
5. **图题**：场景/实物图注明对象，取自文献的图在图题后标引用编号；
6. 无法确认可公开使用的图片，提醒用户确认后再用。

### 5.1 插图数量与文献原图

- 同领域样本全文 13–25 幅图（中位数约 15）。只有项目图和自绘框图（不足 10 幅）时，答辩专家会觉得调研和工作基础单薄。
- 1.2 各小节宜插入 1–2 幅**代表性工作的原图**：如国内外装置或机器人的作业过程图、他人的系统架构图、可达性图/逆可达性图示例。图题写成“图1-n 对象或方法名^[k]^”，正文中用“如图1-n所示”引出并说明这张图说明了什么。
- 优先选开放获取（CC BY）期刊或 arXiv 的图，在《来源与许可》中记录文献、图号、许可；不用付费出版社页面截图。
- 3.2 中可加入孪生模型截图、碰撞模型截图、坐标系示意等，前提是用户真的做出来了（可另给《开题工作》任务清单，让用户先在现有模型上动手做）。

### 5.2 云端无法联网时取原图的办法

云端与用户电脑的终端都可能被网络代理拦截（HTTP 403）。这时用用户电脑上的内置浏览器：

1. 对出版社网站申请访问（MDPI、arXiv、IOP 等开放获取站点；ScienceDirect 常返回 403，放弃）；
2. 打开文章页面，找到原图链接（MDPI 用 `.../article_deploy/html/images/*.png` 原图，arXiv 用 HTML 版中的图片文件）；跨域图片先导航到图片地址本身，再在同源下读取；
3. 在页面 JS 中 `fetch` 原图 → `ArrayBuffer` → base64 存入 `window.__b`，再按约 23 万字符一段分段取回（单次工具输出约 26 万字符上限，两段一组批量取回会自动保存为文件）；在云端按偏移量拼接、base64 解码，用 PIL 校验尺寸；
4. 原图过大（PNG 超过约 2 MB）时，在页面中用 canvas 按原分辨率重新编码为 JPEG（质量 0.95）再取回，不缩小尺寸；
5. 取回后逐张查看有无水印，记录来源与许可。这一过程只把图片读进会话，不在用户电脑上下载文件。
